The loop in depth

The workflow

Six steps, one direction, and a number at every gate. The loop is not a suggestion: it is what makes "close enough" impossible to say and impossible to accept.

  1. 01ScopeOne section, one time range, one fidelity level, written down.
  2. 02RecordFilm the reference exactly as you will film the clone.
  3. 03SpecRows you can check, and unresolved rows you must resolve.
  4. 04BuildImplement against the spec in the project's own stack.
  5. 05VerifyEvery row measured against the pass criteria. Exit 1 on failure.
  6. 06FixChange one thing the report named, then re-record.

1 · Scope

Narrow the target to what was actually asked for: one section, one widget, one time range of a video. Clone the rest of the page and you will spend rounds on motion nobody asked about.

Write it down before capturing, in .refilm/runs/<name>/scope.md:

  • target — the selector or the video time range, and nothing else
  • destination — path and stack; read the project's package.json and existing components first, and reuse the animation library already in the project
  • fidelity — motion, pixel or mixed, and why
  • additions — for mixed, exactly what is being added on top

The fidelity level is decided here, from the words the person used, because it changes what verify treats as a failure. The full comparison.

2 · Record

The capture decides whether every later number means anything. Two rules above all: the reference and the clone are recorded with the same viewport, crop, trigger, duration, fps and clock — and what you record is exactly what was pointed at, not the page around it. 

refilm record --url <url|file.html> --out .refilm/runs/<name>/ref \
  --selector "<section>" --trigger load|scroll|hover|click|move|drag|none \
  --duration 2000 --track "<moving elements>"

--trigger is where most failed runs go wrong. Pick it from how the motion starts, not from what the page is:

3 · Spec

One row per element per property: start, duration, from → to, easing, stagger. Each row carries a source and a confidence, because where a number came from matters as much as the number.

Evidence order of preference. spec never fills a row with a guess.
SourceWhat it readsPrecision
declaredCSS and WAAPI animations in inspect.json: exact delay, duration, easing, per-keyframe offsetsexact — copy it, do not re-measure
trackper-frame element samples in track.json, fitted by refilm fithigh; works for JS-driven motion too
gl-trackanimated uniforms and scene-graph values from a GPU tracehigh, for canvas work

unknownnothing could measure itlisted under unresolved

The spec is the contract. Every row becomes a check in step 5, so a row that is wrong is not a typo — it is a future failed round.

4 · Build

Implement in the project's stack. Adding GSAP to a project that animates with CSS, or Framer Motion to a Vue app, is a change nobody asked for. When nothing exists yet the preference order is: CSS keyframes and transitions → Web Animations API → the framework's own motion library → GSAP for long timelines.

Keep the DOM structure close to the reference's role structure, so the selectors you tracked have equivalents in the clone. And give the clone a way to be filmed identically — a route or a static page at the reference viewport with the same trigger.

5 · Verify

Three commands per round. Keep every round's directory; the progression is part of the report.

refilm record  --url <clone> --out .refilm/runs/<name>/clone-1 \
  --selector "<same>" --trigger <same> --duration <same> --track "<same>"
refilm compare --ref .refilm/runs/<name>/ref/frames \
  --clone .refilm/runs/<name>/clone-1/frames --out .refilm/runs/<name>/compare-1
refilm sheet compare --ref …/ref/frames --clone …/clone-1/frames --diff …/compare-1/diff --out …/compare-1/sheets
refilm verify  --spec .refilm/runs/<name>/spec.json \
  --ref .refilm/runs/<name>/ref --clone .refilm/runs/<name>/clone-1 --out .refilm/runs/<name>/verify-1

The pass criteria, with their real numbers

These are not defaults you can lower when a run is inconvenient. They are the thresholds the gate applies, and verify prints each one next to the measurement it failed.

A skip is not a pass

When a check cannot be measured, verify reports skip with the reason — "the clone's track has 1 start time(s) for 3 siblings: track every sibling to measure the stagger". It never reports a check it could not measure as green. A green run that skipped its checks is worse than a red one, because it is a lie with a number attached.

The fidelity levels

The level decides what gets checked. Pick it before the first capture; changing it later means re-recording.

Default default — —

pixel fails for reasons that have nothing to do with motion, so fix layout and fonts before chasing timing. And keep the level honest: a pixel run that is really a motion run with a loosened threshold is a report that lies.

6 · Fix

Read the report in a fixed order, then change the smallest thing the evidence points at. Each round should be one cause, not five guesses.

When to stop

  • When every spec row passes and the latest sheets show the same state at the same timestamp — and you can say that with numbers.
  • After 5 rounds with no progress on a row, or when the remaining difference is outside your control: a font licence, a shader you may not copy, a third-party embed, physics you approximated. Report the row, its last numbers and the reason.
  • Never by relaxing a threshold. If a looser bar is genuinely right, say which one and why, and let the person decide.
Rules that save rounds

Same capture settings on both sides. A different viewport, crop, fps, trigger or clock means you are measuring your setup. compare warns about it — treat the warning as a failure.

Read the middle frames. Easing lives between the first and last frame; two frames tell you nothing.

Scroll motion is a function of scroll position, not time. Capture both sides with the same --scroll-steps and --scroll-ms.

Canvas on the real clock drops frames. Capture both sides with --clock virtual and the same --seed.
