Canvas, WebGL and 3D

A canvas only shows pixels, so refilm record --gl records the calls that drew them: shader sources, every constant uniform, the render passes, the textures and models, and each animated uniform or scene-graph property as a curve that can be fitted and compared.

Record the trace

refilm record --url https://example.com --out ref \
  --clock virtual --gl --assets --duration 2000 --fps 20
refilm gl summary ref
Three flags, and what each one buys you.
FlagWhat it doesWithout it
--clock virtual the page runs on a clock advanced frame by frame — performance.now, Date, timers, requestAnimationFrame, CSS/WAAPI timing and event timestamps all follow it — with Math.random seeded. Frame k is exactly t = k/fps whatever the GPU or machine load, and two captures of the same scene are byte-identical. a software-GL box drops frames and random particles differ on every load, so the comparison measures the machine
--gl traces WebGL, WebGL2, WebGPU and canvas 2D, and hooks the three.js, Pixi, PlayCanvas, Babylon and OGL scene graphs through their own devtools entry points — including inside workers. you get frames and pixels, but no shaders, uniforms, passes or channels
--assets saves the models, textures, shader files, Lottie/Rive/Spline files and scripts the page loaded. you can read the shader source, but you cannot reuse the model or texture

--gpu software is the default: SwiftShader is slower, but it produces the same pixels on every machine. --gpu hardware uses the real GPU and enables WebGPU. Record both sides with the same mode, or you are comparing two renderers.

Output on disk:

gl/gl.json          gl/draws.json      gl/summary.md
gl/shaders/         gl-track.json      assets/ + assets.json

Channel kinds

Every animated value becomes a channel, and every channel is classified. The classification is the useful part: it tells you how to implement it, not just that it moves.

From refilm gl channels. A channel's kind is what decides the implementation.
KindMeaningHow to implement it
clockadvances linearly with time (+0.9/s)drive it from a clock at that rate
transitionmonotonic move from A to B inside a windowthat window is the duration; fit the easing
there-and-backleaves and returnstwo-phase; note the turn point
oscillationperiodicperiod and amplitude, usually a sine
stepsdiscrete jumpsa state machine, not an interpolation

Reading the trace

refilm gl summary ref
refilm gl channels ref --grep emissive
refilm gl channels ref --series "three:s0/Mesh#2.rotation.x"
# GPU trace: ref

renderer: ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device), SwiftShader driver) · 112 frames traced · 1 draw calls per frame

## Canvases
- c1 webgl on canvas#c: 480×360 px, css 480×360 at 0,0 (pixel ratio 1), antialias true, alpha true

## Programs (shaders in gl/shaders/)
- **p1**: 1/frame, TRIANGLE_STRIP up to 4 verts, no-blend (gl/shaders/p1.vert, gl/shaders/p1.frag)
  - animated: uHover
  - fixed: uTint=[0.35,0.55,1]
  - attributes: p 2×FLOAT buf b1

## One frame per canvas, in draw order (render target: draws)
- c1 canvas#c → screen: p1 TRIANGLE_STRIP 4 [no-blend]

## Animated channels (1; read one with: refilm gl channels <dir> --series KEY)
- p1.uHover: there-and-back, 0.000037791 → 0.99989, changes -650–1183 ms

gl summary separates animated from fixed uniforms, and that split matters: the fixed ones are the art direction. A single wrong constant changes the whole look, so copy them exactly rather than approximating them.

Fit a channel like a DOM property

refilm fit --track ref/gl-track.json --channel "three:s0/Mesh#2.rotation.x"

Same output shape as a DOM track: delay, visible duration, overshoot, settle time, and the best-fitting named easings with an RMSE and a fitted duration each.

Comparing a clone

refilm gl compare --ref ref --clone clone-1 --grep emissive --timing 80
# GPU compare: ref vs clone-1

## Canvases
| canvas   | reference                                                    | clone                                                        |
|----------|--------------------------------------------------------------|--------------------------------------------------------------|
| canvas#c | webgl 480×360 px (ratio 1), antialias true, alpha true        | webgl 480×360 px (ratio 1), antialias true, alpha true        |

## Draw structure (draw calls per traced frame, by primitive · vertices · state)
| draws                          | reference | clone |
|--------------------------------|-----------|-------|
| TRIANGLE_STRIP 4 [no-blend]    | 1         | 1     |

## Animated channels (1 in the reference; uniform time "clock" channels are skipped)
| reference | | clone | timing and value error | result |
|---|---|---|---|---|
| p1.uHover | there-and-back 0.000037791→0.99989 -650–1183 ms | p1.uHover: there-and-back … | start +0 ms, end +0 ms, mean |Δ| 0.0 % of range | pass |

pass: same kind, start and end within 80 ms, mean value error ≤ 5 % of the reference range. 0 of 1 failing.

It checks three layers, in order: canvas attributes and renderer settings, draw structure (primitive, vertex count, blend state, cadence), then every animated channel — same kind, start and end within --timing ms, mean error ≤ 5% of the reference's range. Use --map "uHover=u_hover" when the clone's channel names differ.

Exit code 1 when any channel fails. Same gate contract as verify, so a canvas animation can fail a build the same way a CSS one does.

Building the clone

  1. Same engine, same version

    Port the shaders from gl/shaders/ verbatim where they are yours to use, and keep every constant uniform exactly as recorded.

  2. Copy the fixed uniforms

    They are the art direction, not noise. gl summary already separates them from the animated channels.

  3. Drive each animated channel

    With the timing and easing its curve showed, through the same property — uniform, object transform, camera.

  4. Match the render passes

    A four-pass composite is not one pass with a fancy shader.

  5. Match the renderer settings

    Context attributes, tone mapping, colour space, pixel ratio.

  6. Frame-rate-independent smoothing for pointer values

    x += (target − x) · (1 − (1 − k) ** (dt / 16.67)). A naive lerp(x, target, 0.1) per frame moves at a different speed on a 120 Hz display.

  7. Random content

    If you port the generator, seed it the same way and the particles match dot for dot. If you cannot, say so and compare with compare --blur.

Limits worth knowing

  • Workers are seeded and traced, but their own clocks run in real time.
  • Canvases inside iframes need the iframe's own URL.
  • Random generators you cannot port mean particles are compared with a blurred mismatch — density, colour, motion — instead of dot by dot.
  • Software GL is slow. Keep canvas captures short (≤ 2 s) and the viewport modest.
  • A canvas that renders nothing after a --gl run is usually a script that failed to load. Check the page console before blaming the tracer.
  • Rebuilding a shader from screenshots is wasted work: gl summary already has the source and every constant uniform.
