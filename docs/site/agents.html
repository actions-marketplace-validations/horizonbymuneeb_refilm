Using it from an agent

Any agent that can run a shell command can use refilm. Two things make that reliable rather than lucky: a bundled skill that says when to reach for it, and a machine contract — one JSON envelope, five exit codes — that never requires parsing human output.

The bundled skill

refilm install --agent claude    # also: codex, dsh, all
Targets. all installs into every target whose parent directory exists.
AgentDirectory
claude~/.claude/skills/refilm/
codex~/.codex/skills/refilm/
dsh$DSH_HOME/skills/refilm/, falling back to ~/.dsh-home/skills/refilm/
allevery target whose parent directory exists

The skill is a thin wrapper. It tells the agent when to reach for refilm, how to state a fidelity level, and how to read the numbers — while all the measurement lives in the CLI. It copies SKILL.md and references/ from the package's own skill/ directory, downloads nothing, and touches nothing outside those three paths. --dry-run prints the resolved targets and changes nothing.

The --json envelope

Every command takes --json and prints exactly one envelope on stdout, with logs on stderr. Success and failure share the same shape, so an agent never has to branch on "did this print JSON at all". 

{
  "ok": true,
  "command": "verify",
  "version": "0.1.3",
  "warnings": [],
  "data": {
    "schema": 1,
    "kind": "verify",
    "fidelity": "motion",
    "pass": true,
    "checks": [
      {
        "id": "div-eyebrow-opacity.start",
        "label": "div.eyebrow opacity start",
        "status": "pass",
        "measured": "+0 ms",
        "limit": "±80 ms",
        "detail": "reference -633 ms, clone -633 ms"
      }
    ],
    "counts": { "pass": 49, "fail": 0, "skip": 11 },
    "artifacts": { }
  }
}

And the same shape when it fails — the errors array replaces data:

{
  "ok": false,
  "command": "compare",
  "version": "0.1.3",
  "warnings": [],
  "errors": [
    {
      "code": "USAGE",
      "message": "compare needs --ref <framesDir> --clone <framesDir> --out <dir>",
      "hint": "example: refilm compare --ref .refilm/ref/frames --clone .refilm/clone/frames --out .refilm/diff"
    }
  ]
}
The envelope contract. Nothing may write to stdout except through the reporter.
FieldTypeAlways presentMeans
okbooleanyesthe command succeeded
commandstringyeswhich command produced this
versionstringyesthe refilm version — pin against it
warningsstring[]yes (may be empty)non-fatal problems, for example a setupWarnings mismatch
dataobjecton successthe payload, schema-versioned and kind-tagged
errorsobject[]on failurecode, message and usually a copy-pasteable hint

The exit-code contract

Stable across every command. This is what an agent or a CI job branches on.
CodeNameMeansAgent should
0successthe command did its jobread data, continue
1verification failedthe clone does not match — compare, gl compare, verify, report --checkread the failing checks, fix one cause, re-record. Not a crash.
2usage errora flag is missing or wrong, a path does not existfix the command from the hint; do not retry unchanged
3environment problemnode, ffmpeg or Chromium missing or unusablerun refilm doctor, report the fix line, stop
4internal errora bug, or the browser died mid-capturere-run once; if it repeats, file the envelope
The distinction that matters

1 and 2 are completely different messages. 1 means the tool worked and the clone does not match — keep iterating. 2 means the agent's command was wrong — fix the invocation. An agent that treats both as "error, give up" throws away the entire product.

The CI recipe

An animation regression becomes a red build instead of a review comment nobody can measure. Pin the version: the in-page scripts are part of the capture, so reference and clone should come from the same refilm. 

npx refilm@0.1.3 verify \
  --spec .refilm/runs/hero/spec.json \
  --ref .refilm/runs/hero/ref \
  --clone .refilm/runs/hero/clone-1 \
  --json
name: motion
on: [push, pull_request]
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npx playwright install --with-deps chromium
      - run: npx refilm doctor
      - name: film both sides, then gate
        run: |
          npx refilm@0.1.3 record --url "$REF_URL" --out .refilm/ref \
            --selector ".hero" --trigger load --duration 1800 --clock virtual
          npx refilm@0.1.3 record --url "$CLONE_URL" --out .refilm/clone \
            --selector ".hero" --trigger load --duration 1800 --clock virtual
          npx refilm@0.1.3 verify --spec .refilm/runs/hero/spec.json \
            --ref .refilm/ref --clone .refilm/clone --json

Commit the spec and keep the reference capture as a CI artifact, or re-film the reference on every run — but if you re-film it, use --clock virtual so the reference does not drift. Determinism explains why.

What the agent's loop looks like

  1. State the fidelity level

    From the words used. motion unless the ask was "exactly" or "1:1".

  2. Record, look, spec

    record → sheet filmstrip → spec. Resolve every row in unresolved before writing code.

  3. Build in the project's own stack

    Reuse the animation library already in the repository. Do not introduce GSAP for a CSS project.

  4. Loop on verify's exit code

    Record the clone the same way, compare, sheet compare, verify. Exit 1 names the check; change one cause; repeat. Expect 2–5 rounds.

  5. Report with numbers

    report --dir … for the file, plus a table of the last round: per-check measured vs limit. Every residual deviation gets a number and a reason.

Never lower a threshold to make a run green

If a looser bar is genuinely appropriate — a font licence you do not hold, a particle generator you cannot port — say which threshold and why, and let the person decide. A green run with a quietly relaxed limit is worse than a red one.

Programmatic use

import { record, compare, verify } from "refilm";

const cap = await record({ url: "https://example.com", out: ".refilm/ref", duration: 1800 });
const cmp = await compare({ ref: ".refilm/ref/frames", clone: ".refilm/clone-1/frames", out: ".refilm/cmp" });
if (!cmp.pass) console.log(cmp.failures);

Each helper resolves with the same object the CLI prints under data, so the shape is documented once and tested once.
