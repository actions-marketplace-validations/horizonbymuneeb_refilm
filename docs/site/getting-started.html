Getting started

Install refilm, let it check the machine, scaffold a run directory, then take one animation through the full loop. Every command below is real output from this repository's demo.

Requirements

Checked by refilm doctor. Nothing is downloaded behind your back.
RequirementWhyIf it is missing
Node 20+ the ESM and fetch baseline refilm is built against nvm install 20, or any Node 20+ installer
ffmpeg cutting frames out of the recording, probing a video or gif apt install ffmpeg / brew install ffmpeg, or set REFILM_FFMPEG
Playwright Chromium the browser that films the page npx playwright install chromium

Install

Global install gives you the refilm binary. npx works too and is the better choice for CI, where the version should be pinned by the lockfile.

npm install -g refilm
npx refilm@0.1.3 --version
Upgrading

0.1.0 and 0.1.1 were broken when installed from npm — the published package was missing dist/inpage/, so every refilm record failed with in-page script clock.js not found. 0.1.2 fixed it. Anything at 0.1.2 or later is safe. See the changelog.

Check the machine

doctor runs four required checks and one advisory one, prints the exact command that fixes anything missing, and exits 3 when something required is missing. It installs nothing.

refilm doctor
refilm doctor — ready (4 ok, 1 warn, 0 fail)

  ok    node      v26.7.0
  ok    ffmpeg    6.1.1-3ubuntu5 (on PATH)
  ok    chromium  Playwright Chromium 156.0.8078.4 launches and closes
  ok    writable  /home/you/project is writable
  warn  runDir    no .refilm/ in /home/you/project yet
        fix: refilm init            # scaffolds .refilm/ with runs/ and config.json

ready to film (warnings do not block)

The Chromium check actually launches and closes the browser, so a broken sandbox or a missing shared library fails here rather than three steps into a capture.

Scaffold the project

init creates .refilm/config.json and .refilm/runs/, and adds .refilm/ to .gitignore when a .gitignore exists. It is idempotent: run it twice and it keeps what is already there.

refilm init
  created  .refilm/
  created  .refilm/runs/
  created  .refilm/config.json
  created  .gitignore (+.refilm/)

next:
  refilm record --url <url> --out .refilm/runs/<name>/ref --selector "<section>" --trigger load
  refilm spec   --capture .refilm/runs/<name>/ref --out .refilm/runs/<name>

A first complete run

One section, one trigger, both sides filmed the same way. The reference here is the demo page in demo/reference/index.html: a pricing hero whose eyebrow, heading, sub-paragraph and three cards rise in sequence.

1 · Record the reference

refilm record --url https://example.com --out .refilm/runs/hero/ref \
  --selector ".hero" --trigger load --duration 1800 \
  --track ".eyebrow, h1, .sub, .card"
[launch] chromium (software gl, 1440x900 @1x)
[load] https://example.com
[inspect] animations, keyframes, styles, fonts, libraries
[frames] cutting frames out of video.webm
[write] capture.json
capture     .refilm/runs/hero/ref
page        Pricing hero — https://example.com
viewport    1440x900 @1x · 25 fps · real clock
frames      50 · cropped 1080x409 at 180,245
trigger     load · trigger frame 5 · 1800 ms
motion      9 animations · 3 keyframes · 0 canvases · 33 nodes
track       62 samples of .eyebrow, h1, .sub, .card
renderer    ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device), SwiftShader driver)

--track is the flag that pays for itself: it samples position, size, opacity and transform of each listed element every frame, which is what lets fit name a curve later. Track the elements you will animate, plus any parent that moves.

2 · Look at the frames

The numbers say something is off; the contact sheet says what. Do this before writing any code.

refilm sheet filmstrip --frames .refilm/runs/hero/ref/frames \
  --out .refilm/runs/hero/ref/sheets --cols 6
rendered .refilm/runs/hero/ref/sheets/sheet-01.png

3 · Derive the spec

refilm spec --capture .refilm/runs/hero/ref \
  --out .refilm/runs/hero/spec.json --name hero --md .refilm/runs/hero/spec.md
spec hero — 18 row(s), 3 unresolved, 1660 ms total
# | element        | property   | from → to | start | dur | easing                                | stagger | source   | conf

2 | div.eyebrow    | translateY | 14 → 0    | 0     | 620 | cubic-bezier(0.16, 1, 0.3, 1)/ease-out | –       | declared | high
3 | h1             | opacity    | 0 → 1     | 90    | 760 | cubic-bezier(0.16, 1, 0.3, 1)/ease-out | –       | declared | high
7 | article.card[0]| opacity    | 0 → 1     | 300   | 820 | cubic-bezier(0.22, 1, 0.36, 1)/ease-out | 100     | declared | high
8 | article.card[0]| scale      | 0.97 → 1  | 300   | 820 | cubic-bezier(0.22, 1, 0.36, 1)/ease-out | 100     | declared | high
…

unresolved (3):
  - .card.scaleY moves in the track (331 ms, 666 ms) but no declared animation explains it — likely a transition or a JS tween
  - .card.x moves in the track (331 ms, 791 ms) but no declared animation explains it — likely a transition or a JS tween
  - no fonts recorded in the capture: font family, weight and rendering are unverified, which pixel fidelity cannot survive

Resolve the unresolved rows before you build. They are the honest half of the spec: three things the evidence could not answer. Read more frames, track another element, or ask the person who asked for the clone. Do not fill them with a guess and let them look measured.

4 · Build the clone

Implement in the project's own stack, from the spec rows — not from the screenshot. If the project already animates with CSS, do not add GSAP for this. Then give the clone a way to be filmed identically: a route or a static page that renders the component at the reference viewport with the same trigger.

5 · Re-film the clone and verify

refilm record --url http://localhost:5173 --out .refilm/runs/hero/clone-1 \
  --selector ".hero" --trigger load --duration 1800 \
  --track ".eyebrow, h1, .sub, .card"
refilm compare --ref .refilm/runs/hero/ref/frames \
  --clone .refilm/runs/hero/clone-1/frames --out .refilm/runs/hero/compare-1
refilm verify --spec .refilm/runs/hero/spec.json \
  --ref .refilm/runs/hero/ref --clone .refilm/runs/hero/clone-1 \
  --out .refilm/runs/hero/verify-1
verify hero — motion fidelity: 12 pass, 37 fail, 11 skip
  PASS div.eyebrow opacity start — -34 ms (limit ±80 ms)
  FAIL div.eyebrow opacity end — -209 ms (limit ±80 ms)
       reference 635 ms, clone 426 ms
  FAIL div.eyebrow opacity easing — ease-out → linear (limit family ease-out, or ≤5% of travel)
       the clone is linear where the reference is ease-out: that is a different kind of motion, not a near miss (curve distance 4.1%)
  …
  FAIL article.card stagger — -100, -100 ms (limit ±40 ms)
       spec gaps 100, 100 ms; clone gaps 0, 0 ms
  PASS nothing extra is moving — 0 (limit 0)

result: FAIL — 37 check(s) failed (exit 1)
note: 11 check(s) skipped; a skip is not a pass — see the reasons above

Exit code 1. That is not an error, it is the gate doing its job: an agent or a CI job can loop on it without reading a single line of prose.

6 · Fix what it named, and go again

Round 1 was 420 ms linear with no stagger. Round 2 sets the declared durations and the real cubic-beziers, and adds the per-card delay: 

verify hero — motion fidelity: 49 pass, 0 fail, 11 skip
  PASS div.eyebrow opacity start — +0 ms (limit ±80 ms)
  PASS div.eyebrow opacity easing — ease-out-expo → ease-out-expo (limit family ease-out)
  PASS article.card stagger — -23, -5 ms (limit ±40 ms)
  …
result: PASS (exit 0)
note: 11 check(s) skipped; a skip is not a pass — see the reasons above
Why 49 and not 60

Eleven checks were skipped because the capture could not measure them — for example div.bar[0] scaleX was never in --track, so its timing has no series to compare. A skipped check names what was missing. Add the selector to --track and re-record if you want it measured.

7 · Produce the report

refilm report --dir .refilm/runs/hero --out .refilm/runs/hero/report.html
wrote .refilm/runs/hero/report.html (61.8 KB, 2 round(s), 18 spec row(s))
external references: 0 — opens offline

One self-contained file with every round, the spec, the sheets and the numbers. --check re-reads a report already on disk and exits 1 if it would make any external request.
