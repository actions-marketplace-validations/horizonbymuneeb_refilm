Command reference

refilm compare

Diff a clone's frames against the reference's, frame by frame.

Writes files on disk JSON --json Exit 0 · 1 · 2

Synopsis

refilm compare --ref <framesDir> --clone <framesDir> --out <dir> [options]

Flags

From refilm compare --help.
FlagTypeDefaultWhat it does
--auto-align flag on Find the clone offset within ±--max-shift that best matches the reference.
--offset K number auto Use a fixed offset instead: clone frame = reference frame + K.
--max-shift N number 15 Auto-align search range, in frames.
--region x,y,w,h numbers whole frame Compare only this rectangle, in reference pixel coordinates.
--pixel-threshold T 0..1 0.1 pixelmatch colour tolerance. Raise it to forgive anti-aliasing.
--threshold T 0..1 0.05 Pass if mean mismatch ≤ T. Use 0.01 for pixel work.
--motion-threshold T seconds 0.08 Pass if every |timing error| ≤ T seconds.
--fps N number 25 Frame rate. Default comes from frames.json beside --ref, else capture.json, else 25.
--blur R px 0 Box-blur both sets by R px before comparing (particles, grain, noise). Reports the blurred and the sharp mismatch.
--no-diffs flag off Do not write diff PNGs.

What it writes

Paths are relative to the directory you pass on the command line.
WritesWhat is in it
report.jsonthe same numbers as report.md, typed.
report.mdoffset, mean mismatch, motion window, timing error, worst frames, the per-frame activity chart.
diff/NNNN.pngred where the pixels differ. Suppressed by --no-diffs.

Exit codes

Exit codes. The full contract is on Using it from an agent.
CodeMeaning
0the comparison passed
1the comparison failed — mismatch over threshold or timing error over --motion-threshold
2usage error — a path is not a frame directory

Example

refilm compare --ref .refilm/runs/hero/ref/frames \
  --clone .refilm/runs/hero/clone-1/frames --out .refilm/runs/hero/compare-1
# compare — reference vs clone

- frames: 46 compared of 50 reference frames at 25 fps, 1080x408, clone offset -4 (auto-aligned)
- mean mismatch: **6.57%** (limit 5.00%) → FAIL
- worst frames: #18 9.5% @0.72s, #19 9.5% @0.76s, #17 9.4% @0.68s
- motion window — reference 3–20 (0.72s, peak #3); clone 8–14 (0.28s, peak #14)
- timing error (clone − reference): start 0.200s, end -0.240s, duration -0.440s, peak 0.440s (limit ±0.08s)

Notes

Read setupWarnings first

If the two captures were made with different viewport, fps, trigger, clock or seed, nothing below means anything. Re-record before changing code.

A large offset is a trigger problem

Not a rendering problem. Fix the delay or --wait-before, and do not let auto-alignment hide it.

Exit 1 is a result, not a crash

Same contract as verify: a CI job can gate on it.
