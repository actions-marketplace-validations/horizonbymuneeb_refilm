Command reference

refilm fit

Which easing is this curve, and how long does it actually run?

Writes files on disk JSON --json Exit 0 · 2

Synopsis

refilm fit --track <track.json> --selector <css> --prop <x|y|w|h|opacity|scale|translateX|translateY|rotate>
refilm fit --series '[[0,0],[100,12],[200,40],[300,80]]'
refilm fit --track <gl-track.json> --channel <key>
refilm fit --track <track.json> --selector .hero --prop y --compare-track <other.json>

Flags

From refilm fit --help.
FlagTypeDefaultWhat it does
--track <file> file — A track.json or gl-track.json.
--selector <css> css — Element to read from a DOM track.
--prop <p> enum — x, y, w, h, opacity, scale, translateX, translateY, rotate.
--series '[[t,v],…]' json — Fit a curve you already have, with no track file.
--channel <key> string — Channel of a gl-track.json.
--from-ms T / --to-ms T ms whole curve Clip the curve before analysis, in ms of reference time.
--compare-track <file> file — Diff this curve against another track's curve.
--compare-channel <key> string — Channel of the comparison gl-track.
--top N number 5 How many easing candidates to report.

What it writes

Paths are relative to the directory you pass on the command line.
WritesWhat is in it
nothingprints to stdout. With --json the payload is on stdout too.

Exit codes

Exit codes. The full contract is on Using it from an agent.
CodeMeaning
0the curve was analysed
2usage error — no track, unknown property, no such file

Example

refilm fit --track .refilm/runs/hero/ref/track.json --selector ".card" --prop translateY
start 38 → end 0 (change -38)
delay 300ms · visible duration 333ms · overshoot 0% · settles 517ms after it starts
verdict: ease-out-quint over ~820ms (good fit)

best fits (rmse over the normalised curve, duration fitted):
   1. ease-out-quint         rmse 0.0000  ~820ms  cubic-bezier(0.22,1,0.36,1)  [ease-out]
   2. ease-out-quint-alt     rmse 0.0022  ~834ms  cubic-bezier(0.23,1,0.32,1)  [ease-out]
   3. ease-out-quart         rmse 0.0027  ~690ms  cubic-bezier(0.25,1,0.5,1)   [ease-out]
   4. ease-out-expo-alt      rmse 0.0036  ~1013ms cubic-bezier(0.19,1,0.22,1)  [ease-out]
   5. ease-out-expo          rmse 0.0058  ~938ms  cubic-bezier(0.16,1,0.3,1)   [ease-out]

Notes

Take bestFits[0] as the easing to declare

The bezier is ready to paste into CSS. Rebuild with the fitted duration, then re-run fit on the clone's track — a curve that fits the same easing with a low RMSE is a motion match even when the pixels are still off.

Works on JS-driven motion

--playback-rate only slows CSS/WAAPI animations. GSAP, Framer springs and rAF loops are measured here instead: overshoot and settle time give you the spring parameters.

Springs from measurements

10% overshoot → ζ ≈ 0.59, 5% → 0.69, 20% → 0.46. settle ≈ 4 / (ζω) with ω = √(stiffness/mass).
