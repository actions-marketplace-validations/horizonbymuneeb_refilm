Command reference

refilm spec

Derive the motion spec from a capture, a frame set, a Lottie file or a track.

Writes files on disk JSON --json Exit 0 · 2

Synopsis

refilm spec --capture <captureDir>
refilm spec --frames <framesDir|video|gif>
refilm spec --lottie <file.json>
refilm spec --track <track.json>

Flags

From refilm spec --help.
FlagTypeDefaultWhat it does
--capture <dir> dir — Read inspect.json, track.json and gl-track.json from a record output.
--frames <dir|file> dir|file — Pixels only: a video, a gif or a numbered frame set.
--lottie <file> file — The file is the spec; layers are read directly.
--track <file> file — Add fitted rows from a track. Alone, or alongside --capture.
--name <name> string capture dir name Spec name.
--out <file> path <capture>/spec.json Where to write the spec.
--md <file> path — Also write the human-readable template.
--destination <path> string — Where the clone will live: a component path, a stack.
--fidelity <level> motion|pixel|mixed motion Sets the level the spec is written for, and the checks verify applies by default.
--additions "a,b" list — What is being added on top. For --fidelity mixed.
--json flag off Machine-readable result.

What it writes

Paths are relative to the directory you pass on the command line.
WritesWhat is in it
spec.jsonrows with element, property, from → to, start, duration, easing, stagger, source, confidence; plus unresolved.
<md>the same content as a readable template, when --md is given.

Exit codes

Exit codes. The full contract is on Using it from an agent.
CodeMeaning
0the spec was written
2usage error — no source, or the path is not a directory

Example

refilm spec --capture .refilm/runs/hero/ref \
  --out .refilm/runs/hero/spec.json --name hero --md .refilm/runs/hero/spec.md
spec hero — 18 row(s), 3 unresolved, 1660 ms total
# | element        | property   | from → to | start | dur | easing                                | stagger | source   | conf
1 | div.eyebrow    | opacity    | 0 → 1     | 0     | 620 | cubic-bezier(0.16, 1, 0.3, 1)/ease-out | –       | declared | high
7 | article.card[0]| opacity    | 0 → 1     | 300   | 820 | cubic-bezier(0.22, 1, 0.36, 1)/ease-out | 100     | declared | high
…

unresolved (3):
  - .card.scaleY moves in the track (331 ms, 666 ms) but no declared animation explains it — likely a transition or a JS tween
  - no fonts recorded in the capture: font family, weight and rendering are unverified, which pixel fidelity cannot survive

wrote .refilm/runs/hero/spec.json
wrote .refilm/runs/hero/spec.md

Notes

Evidence order is fixed

declared (CSS/WAAPI keyframes) → track (fitted from samples) → gl-track (GPU channels) → frames (pixels only) → unknown. A stronger source supersedes a weaker one and says so.

unresolved is the honest half

Anything the evidence cannot measure is listed there and its row marked confidence: low. Nothing is guessed to fill a row. Resolve those before building.

The spec is the contract

Every row becomes a check in verify. A wrong row is not a typo, it is a future failed round.
