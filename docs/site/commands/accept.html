Command reference

refilm accept

Promote a clone to be the new reference, with a backup and an audit trail.

Writes reference frames, backup, ACCEPTED.md JSON --json Exit 0 · 2

Synopsis

refilm accept --ref <framesDir> --from <cloneDir> [options]

Why this exists

Every visual-regression tool needs a way to say "the design changed on purpose, the clone is right". Doing that with cp loses the provenance — what was replaced, when, and why. accept keeps all three and never leaves the old reference unrecoverable.

Flags

FlagMeaning
--refReference capture directory (the one being replaced).
--fromThe clone to promote — a capture directory or a bare frames directory.
--reasonWhy the baseline moved. Written verbatim to ACCEPTED.md.
--dry-runPrint the plan; write nothing.
--jsonMachine-readable result.

What it writes

  • <refDir>.bak-<timestamp>/ — the previous reference (frames and its metadata)
  • <refDir>/frames/ — replaced with exactly the clone's frames (a shorter clone leaves no stale tail)
  • <refDir>/capture.json, frames.json, track.json — carried over when present
  • <refDir>/ACCEPTED.md — appended audit trail: time, reason, frame counts, page URL

A worked accept

refilm compare --ref .refilm/hero/ref --clone .refilm/hero/clone-1 --out .refilm/hero/diff
# the diff is what you wanted, and the change is intentional:
refilm accept --ref .refilm/hero/ref --from .refilm/hero/clone-1 --reason "new hero easing, DS-214"

The audit trail

## 2026-10-31T20:35:11.578Z

- accepted: 76 frame(s) from `/work/.refilm/hero/clone-1`
- previous reference: 73 frame(s) — backed up to `/work/.refilm/hero/ref.bak-2026-10-31_20-35-11`
- metadata carried over: capture.json, frames.json
- page: file:///work/.refilm/hero/clone-1/index.html
- reason: new hero easing, DS-214

Exit codes

CodeMeaning
0Accepted (or a dry run)
2Usage error: missing flags, missing directory, or a clone with no frames
