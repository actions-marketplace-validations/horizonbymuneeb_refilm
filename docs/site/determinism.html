Topic

Determinism

Same input, same output. Every number refilm reports rests on this: if two captures of the same page could differ, a comparison would be measuring the machine instead of the clone.

How the guarantee is made

Under --clock virtual the page does not run on the wall clock. The capturer owns time and advances it by hand, frame by frame:

  • performance.now and Date return the virtual time
  • setTimeout, setInterval and requestAnimationFrame fire on it
  • CSS and WAAPI animation time follows it
  • event timestamps follow it
  • Math.random is seeded, so --seed 1 produces the same particles every time

The consequence is the sentence the whole tool is built on: frame k is exactly t = k/fps, however slow the machine is. A frame that took 40 ms to render and one that took 400 ms land at the same timestamp, so a dropped frame cannot shift the time base.

Why it had to be built

Without it, a software-GL box drops frames and random particles differ on every load. The comparison then reports the difference between two runs of your machine, which is noise wearing the costume of a measurement.

Verify it yourself

Two captures, one page, the same seed. The frame hashes are identical — and you can check that with two commands and no refilm-specific tooling: 

refilm record --url ./page.html --out a --clock virtual --seed 1 --duration 1500
refilm record --url ./page.html --out b --clock virtual --seed 1 --duration 1500
cd a/frames && sha256sum *.png | md5sum
cd ../../b/frames && sha256sum *.png | md5sum
1a6517c65e84eccf241a97745a1025b2  -
1a6517c65e84eccf241a97745a1025b2  -

One frame at a time, if you want to see the actual hashes rather than a digest of the list:

sha256sum a/frames/0007.png b/frames/0007.png
95b67dc2b0766bd8aec8f8424b468da4cb896ea8a8e199ce851237682d9d3e3e  a/frames/0007.png
95b67dc2b0766bd8aec8f8424b468da4cb896ea8a8e199ce851237682d9d3e3e  b/frames/0007.png

This holds for DOM pages and for WebGL scenes. The test suite asserts it too: one test hashes every frame of two --clock virtual captures, and a control fixture uses real Math.random so the seed cannot be silently ignored and still pass.

What it does not cover

Where the guarantee stops. Each row is a real limit, not a disclaimer.
CaseByte-identical?Why
--clock real No the page runs on the wall clock and the frames are cut out of an encoded video; encoding and dropped frames make two runs differ. Two real-clock captures of the same page hash differently — that is expected, and it is why canvas work must use --clock virtual.
workers' own clocks partly workers are seeded and traced, but their own clocks run in real time
network content no a page that fetches live data, an ad, a font from a CDN or a random image will differ. The guarantee is about time, not about what the server sent.
--gpu hardware vs software no two different renderers. Identical pixels are a software-GL promise; record both sides with the same --gpu mode.
a different --seed no different random stream, different particles — by design. Use the same seed on both sides.
different refilm versions not promised the in-page scripts can change between versions. Compare captures made with the same version.

Why compare reads capture.json

Determinism is a property of one capture; a meaningful comparison is a property of two. So compare reads capture.json on both sides and warns when the viewport, fps, trigger, clock or seed disagree: 

setupWarnings:
  - viewport differs: reference 1440x900, clone 1280x800
  - clock differs: reference virtual (seed 1), clone real

Treat that warning as a failure. It does not mean the clone is slightly off — it means the comparison is not measuring the clone at all.

The rules that follow

  1. Same settings on both sides

    Viewport, crop, fps, trigger, duration, clock, seed. Change only --url and --out between the reference and the clone.

  2. Virtual clock for anything with a canvas

    Real-clock canvas captures drop frames, and the drop depends on the machine. Canvas and 3D.

  3. Keep captures short

    ≤ 3 s on a software-GL box. Long captures drop frames even on the virtual clock if the page is expensive.

  4. Same refilm version both sides

    Pin it in CI: npx refilm@0.1.3 verify ….
